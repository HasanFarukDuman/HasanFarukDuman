P1 · Digital design · RTLMilli Teknoloji Akademisi, Chip Design Specialization Program · 2025

UART-controlled waveform generator with SPI DAC output

A complete digital signal chain written in Verilog: a serial command arrives over UART, a decoder turns it into a waveform type and rate, a generator produces 8-bit samples, and an SPI driver streams them to a PMOD DA1 DAC. Every block was verified with its own testbench, then the full chain was simulated end to end.

My role

Specification, micro-architecture, RTL, testbenches and documentation of all four modules, delivered week by week with teammate Melike Atay Karabalkan. One of 60 participants admitted to the specialization stage from 500 in the foundation program.

How each block works

cmd_handler. A small FSM (IDLE → WAIT_FREQ → IDLE) interprets the byte stream. A waveform letter is held while the next byte is passed through map_baudrate(), which maps codes 0x01–0x05 to five standard rates and ignores anything else. Letter and code are packed into a 16-bit cmd word, and cmd_ready pulses for one clock cycle. Logic is synchronous to clk with an asynchronous reset.

wave_gen. The rate code sets a clock divider; each time the counter reaches clk_divider a tick advances the waveform. Sawtooth counts 0→255 and wraps, triangle reverses at the peaks through a direction register, and square takes the MSB of the internal counter.

pmod_driver. Each new sample is latched, combined with eight control bits into a 16-bit SPI word and shifted out MSB-first by a four-state FSM (IDLE → LOAD → SHIFT → DONE). SYNC stays low for the 16 clocks of the frame and busy handshakes with the generator.

Verification

  • Unit testbenches per module, waveforms dumped to VCD and inspected in GTKWave; each module synthesized with Yosys to check the inferred logic.
  • Top-level testbench drives two commands through a send_uart task: 'A' + 115200 (cmd = 0x4105), then 'C' + 9600 (cmd = 0x4301).
  • Observed: clk_divider switches from 0x364 (868) to 0x28B0 (10 416), the output changes from a sawtooth ramp to a square wave, and every sample triggers a complete 16-bit SPI transfer with SYNC and busy framing it.
  • The program’s final stage took the design through the OpenLANE flow (synthesis, place & route, GDSII) using scripts I prepared.

24 V / 60 A sensorless BLDC motor driver

A custom driver for the team’s fixed-wing UAV propulsion motor. It commutates a brushless motor without Hall sensors by reading the back-EMF of the undriven phase, and it went from breadboard to a fabricated, hand-assembled board.

Electronics team lead. I owned the hardware design and the core firmware architecture: component selection, schematic, layout, prototype bring-up, fabrication and soldering.

Design decisions

  • IRF3205 MOSFETs for the high-current switching requirement at 24 V; dedicated high/low side drivers for safe, efficient gate triggering.
  • Power stage and control stage physically separated on the board for EMI/EMC stability.
  • Layout optimized for a compact footprint, low noise and controlled heat spreading around the three phase-output clusters.
  • A virtual neutral point lets the BEMF of each floating terminal reach the MCU’s analog inputs without a motor neutral wire.

Bring-up and verification

  • First prototype assembled on a breadboard; IR2104 outputs and MOSFET switching behavior checked on the oscilloscope.
  • MOSFET triggering tested with basic PWM signals, then the motor was spun under software control.
  • Board fabricated and assembled by hand as BLDC_DRIVER_BEMF_SENSING.

PCF8574 I²C driver library for a 16×2 character LCD

A reusable C driver that runs an HD44780-compatible 16×2 LCD through a PCF8574 I²C port expander on a Nuvoton M032 board. The display hangs off the shared two-wire bus instead of taking a parallel port, which frees GPIO for the rest of the application.

Platform
Boardoza M032 Educational Development Kit
MCU
Nuvoton M032KG8AE · Arm Cortex-M0
Bus
I²C master · SCL + SDA
Expander
PCF8574 · 8-bit quasi-bidirectional I/O
Display
16×2 character LCD · HD44780-compatible
Interface mode
4-bit, one nibble per pair of I²C writes
Language
C
My role

I wrote the driver library and brought it up on the Boardoza M032 kit: I²C configuration, the LCD initialization sequence, command and character writes, and the API the application calls.

GPIO cost

Direct 4-bit parallel6 GPIO
Via PCF85742 pins

RS, EN and D4–D7 with RW tied low, versus SCL and SDA, which other I²C peripherals can share.

What the driver puts on the bus

Type on the display, then tap any character. The panel shows the exact I²C writes the driver makes to print it: one character costs four data bytes, because each nibble has to be strobed with EN high and then EN low.

I²C transaction

    Initialization the driver performs

    1. Wait for the LCD supply to settle after power-up (> 40 ms).
    2. Send the 8-bit wake-up nibble 0x3 three times with the required delays, so the controller starts from a known state whatever mode it powered up in.
    3. Send 0x2 to switch the interface to 4-bit mode; from here every byte goes out as two nibbles.
    4. Function set 0x28: 4-bit, two lines, 5×8 dots.
    5. Display on 0x0C, clear 0x01 (the slowest command, about 1.5 ms), entry mode 0x06 so the cursor moves right after each character.

    What the library handles

    • A single low-level write that packs a nibble with RS, RW and the backlight bit and pulses EN, used by every higher function.
    • Separate paths for instructions (RS = 0) and character data (RS = 1).
    • Cursor positioning from row and column: DDRAM address 0x00 + col for line 1 and 0x40 + col for line 2, sent as command 0x80 | address.
    • Clear, home, string printing and backlight control, with the backlight state kept in the shadow byte so ordinary writes never switch it off.

    Drive-test data to a calibrated propagation model

    Field measurements from cellular drive tests (RSSI, RSRP, RSRQ, SNR) were used to fit a Motley–Keenan path-loss model per environment, then wrapped in a calculator so planners can predict coverage without re-deriving the parameters.

    Measured
    RSSI · RSRP · RSRQ · SNR
    Model
    Motley–Keenan path loss
    Fitted per env.
    n · wall loss · shadowing
    Environments
    Rural LOS · Open area LOS · Urban NLOS · Indoor office NLOS
    Output
    Loss budget + Rx power vs. distance
    My role

    Collected the drive-test data with field measurement systems and mobile devices, optimized the model parameters against serving-cell information, and built the calculation interface.

    The model

    PL(d) = PL(d₀) + 10·n·log₁₀(d / d₀) + Σ Lwall + Xσ PL(d₀): free-space loss at reference distance d₀ · n: path-loss exponent · Lwall: wall penetration losses · Xσ: log-normal shadowing. n, Lwall and σ were fitted for each environment type from field data.

    Worked example from the tool · 5 GHz, d = 50 m, n = 2

    Reference PL(1 m)
    46.42 dB
    Distance term
    33.98 dB
    Wall loss
    0.00 dB
    Shadowing Xσ
    −0.96 dB
    Total path loss
    79.44 dB

    λ = c / f = 0.06 m, so the 1 m reference loss is 20·log₁₀(4π/λ) = 46.42 dB, and 10·2·log₁₀(50) = 33.98 dB. With a 30 m mast and a 1.5 m target the tool computes a target elevation of atan(28.5 / 50) = 29.68°, used to adjust antenna gain for tilt.

    Power conversion prototypes

    Two boards from my hardware design internship: a regulated 3.3 V supply laid out on four layers, and a low-voltage induction heater characterized under load.

    4-layer buck converter

    A fixed 3.3 V supply from a wide 5–18 V input, designed for high efficiency and low EMI. The four-layer stack-up gives power and ground their own planes, which shortens return paths and improves heat spreading.

    Input
    5 – 18 V
    Output
    3.3 V fixed
    Controller
    LT1618
    Stack-up
    4 layers · dedicated PWR + GND planes
    Result
    Stable output, low ripple, good thermals

    Low-voltage induction heater

    An induction heating prototype running from a 12 V DC supply, built around fast MOSFET switching with a Mazzilli driver topology. The goal was to heat from a low-voltage source and study how the resonant circuit responds when a load enters the coil.

    Supply
    12 V · 3 A DC
    Switch
    IRF530N MOSFET
    Diode
    DSA20C150PB Schottky
    Under load
    Waveform shift · current ↑ · coil temp ↑

    With a metal spoon placed in the coil, the switching waveform changed shape, supply current rose and the work piece heated noticeably: the signature of energy coupling into the load.
